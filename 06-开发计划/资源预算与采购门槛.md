# 资源预算与采购门槛

状态：预算方法与批准门槛；无已批准金额、采购订单、付费服务开通或设备到位声明。

基准日：2026-10-22。

## 1. 不先把愿景变成购物清单

首阶段优先盘点现有设备、实验室借用条件和已有计算资源。基础字幕与可控提示研究不强制购买最新眼镜、Apple Watch 或 Aria；可选生理／运动研究必须先证明其问题与可用访问路线。

资金应同时覆盖参与者时间、沟通无障碍支持、标注与隐私管理。只有硬件、没有可访问的研究安排，不能构成可执行预算。

本项目首年核心不需要自研 PCB、定制光学、传感器电路或自建基础模型。以后若确有必要，应以已经观察到的研究限制另行提出，不从当前概念直接扩张。

## 2. 资源盘点与配置层级

| 类别 | 最低可行需求 | 优先取得方式 | 当前状态 |
| --- | --- | --- | --- |
| 显示与同伴计算 | 一套已验证、获准测试的显示路线，及兼容手机／开发计算机 | 先盘点、借用；采购前实测接口 | 项目可用库存尚未核实 |
| 音频 | 一条有合法同意且时间戳可解释的输入路线 | 现有手机／麦克风或授权回放 | 待路线选择与验收 |
| 实验材料 | 目标语言、许可明确、包含误差与重叠的对话材料 | 自有获准材料或批准后的采集 | 待材料权限与研究协议 |
| 人员与沟通支持 | 招募联络、参与者补偿、偏好匹配的沟通支持 | 与研究机构及社区伙伴协商 | 需负责人确认 |
| 标注与分析 | 受训标注、必要复核、版本管理与安全存储 | 现有机构服务优先 | 待工时与数据方案 |
| 模型与计算 | rules 基线；仅在批准后增加云或本地模型资源 | 现有工作站／机构额度先测 | 无新增付费承诺 |
| Apple Watch 分支 | 仅当问题需要且有可用授权 HR／HRV 时启用 | 优先已有、同意使用的设备 | 可选，不阻塞基础版本 |
| 连续 EMG 分支 | 研究访问、兼容采集组合、校准与同步 | 先申请／合作确认，再讨论资源 | 可选，访问未取得 |

Meta 设备和 API 的前提见 [META-01](https://developers.meta.com/wearables/device-access-toolkit/)、[META-02](https://github.com/facebook/meta-wearables-dat-ios/blob/main/CHANGELOG.md)。Aria 的研究流与申请见 [META-04](https://facebookresearch.github.io/projectaria_tools/gen2/ark/client-sdk/changelog)、[META-05](https://ai.meta.com/aria-application/)。买到硬件不等于自动获得研究数据或发布资格。

配置按三个层级报价，避免一次承担所有扩展：

1. **复用／回放层**：现有计算机、获准材料、规则与模拟界面；形成协议和离线评估，但不宣称实际眼镜体验已验证。
2. **核心实机层**：已经验证的显示、手机、音频与参与者访问支持；用于核心先导和研究。
3. **可选扩展层**：HR／HRV 或连续 EMG，仅在额外问题、访问、伦理与同步可行时单独申请。

## 3. 预算公式

所有价格以实际地区、币种、税费、时间和书面报价为准。本文不填厂商价格，也不把模型文档价格当整个系统成本。

建议总预算：

**B_total = B_equipment + B_access + B_participants + B_annotation + B_compute + B_data + B_operations + B_contingency**

| 项目 | 估算方法 | 不能遗漏的内容 |
| --- | --- | --- |
| B_equipment | 经批准数量 × 到手单价，或借用／租用费 | 税费、配件、维护、清洁、损坏责任、归还 |
| B_access | 沟通支持小时 × 当地费率 ＋ 必要场地／交通支持 | 按参与者偏好安排，不以最低价替代可用性 |
| B_participants | 参与人数 × 每人预计时间 × 批准补偿率 ＋ 约定报销 | 先导、主研究、退出与取消规则分别说明 |
| B_annotation | 音视频时长 × 标注工时系数 × 工时费率 ＋ 复核 | 目标语言能力、重叠、分歧复核和培训 |
| B_compute | 本地运行成本 ＋ 云计算量 × 合同单价 ＋ 模型 API 用量 | 回放次数、失败／重试、开发与主实验分开 |
| B_data | 经批准存储量 × 保留期 × 单价 ＋ 备份／删除管理 | 权限、访问审计、加密和到期清除 |
| B_operations | 必要账号、开发许可和研究运行费用 | 机构已有额度不能重复计费；分发资格另审 |
| B_contingency | 负责人批准的风险准备金或比例 | 写明触发条件，不能变成无限追加额度 |

模型用量可按“会话数 × 每会话候选请求数 × 每请求输入量 × 合同单位价格”估算，并增加事先批准的重试上限。缓存是否允许、哪些字段可复用和保留多久，由数据协议决定，而不是只按省钱目标决定。

Jev 的版本与计费单位应在实际开通时重新核对；本文不授权开通服务。[JEV-01：Models](https://docs.typesafe.ai/models)

尚无批准金额不等于预算为零，也不等于可以先支出再补手续。需要负责人在采购／付费前记录总上限、各分支上限、币种、批准日期和责任人；没有这些信息的分支维持“不支出”状态。

## 4. 采购与开通前的五项核对

以下内容合并为一次具体资源决策，不要求逐项重复请求确认。已有授权和预算覆盖的资源可直接按范围复用；常规文档、只读核验和可逆实现按当前任务授权继续。真实采购或付费前，汇总选定资源、报价与仍存在的缺口供负责人决定。

| 门槛 | 必须出示的证据 | 不满足时的动作 |
| --- | --- | --- |
| B0 问题必要性 | 该资源解决哪个已经定义的研究／验收问题，现有方案为什么不足 | 留在复用或模拟层，不采购 |
| B1 接口与访问 | 官方能力、真实账户／设备权限、兼容版本和可用测试／分发路径 | 优先借机或询问访问条件，不能靠购买猜测 |
| B2 许可与数据 | 代码／权重／服务许可、人员同意、处理条款、存储和删除责任 | 缺少许可时只用允许材料；不扩张数据用途 |
| B3 性能与替代 | 最小实测记录、时延／时效、失效恢复，及较低成本替代比较 | 无法借测时明确采购验证风险及退出条件，限制试购范围 |
| B4 预算与责任 | 当前报价、数量、到手总额、预算上限、维护和退还责任 | 按已有明确授权执行，超出时汇总具体选项再决策 |

核心显示设备、Apple Watch、连续 EMG 与付费模型分别计入相应分支预算；同一已有授权可以覆盖多个分支，按实际范围执行。

## 5. 不应用采购“解决”的问题

- **原始 EMG 访问未落实**：先确认专门研究访问与采集路线；不能假定多买 Neural Band 就获得传感器权限。[META-03](https://www.meta.com/en-gb/blog/meta-ray-ban-display-ai-glasses-connect-2025/)；[META-04](https://facebookresearch.github.io/projectaria_tools/gen2/ark/client-sdk/changelog)
- **健康数据不是即时到达**：先验证四层时间语义；更换到新手表不自动获得高频第三方投递。[APPLE-01](https://support.apple.com/en-us/120277)；[APPLE-02](https://www.apple.com/health/pdf/Heart_Rate_Accuracy_Study_2026.pdf)
- **云端数据不获批准**：切换到规则／批准的本地替代，而不是擅自购买另一家云服务。[JEV-04](https://help.typesafe.ai/articles/5974925716-how-is-submitted-data-used-or-retained)
- **所需实验功能尚不能用于发布**：缩小功能或使用获准测试路线；购买开发硬件不改变发布规则。[META-02](https://github.com/facebook/meta-wearables-dat-ios/blob/main/CHANGELOG.md)
- **研究任务或指标不清**：先完善问题、共创与测量，不用更多传感器替代方法学决策。

## 6. 成本监测与暂停

进入实施后，建议每周按分支记录已承诺、已发生、剩余额度和预计完工成本。API 设置请求／费用告警和硬上限；重试量、缓存量与保留量都纳入监测。达到上限后停止可选云调用，不影响用户停止控制，不自动扩容。

设备损坏、无法续借、权限变化或招募困难触发的是重新规划，不是默认追加采购。参与者补偿和沟通支持不得为维持可选模型或额外传感器而被无说明削减。

当前需要负责人决定：可用库存、主研究语言与场地、补偿和沟通服务标准、总预算上限、云处理是否许可，以及是否启动腕部数据扩展。确认前可以继续文档与获准材料的离线设计，但不能声称资源已经落实。
