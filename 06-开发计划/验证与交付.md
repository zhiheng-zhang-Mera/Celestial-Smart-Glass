# 验证与交付

## 1. 四种结果分开

| 层次 | 需要的证据 | 本次初始化状态 |
|---|---|---|
| 文档交付 | 文件完整、导航可达、引用、范围与条件一致、远端内容核对 | 在初始化记录中填写实际检查结果 |
| 平台验证 | 具体设备 / 账号 / SDK 上的真实访问、时间和失败记录 | `NOT_RUN` |
| 软件功能验收 | 正常入口、真实能力、构建身份、断线 / 拒绝 / 取消、视频与日志 | `NOT_RUN` |
| 研究结论 | 批准、冻结方案、合格数据、分析和限制 | 尚未开始 |

文档审阅或另一个代理赞同，不等于不同主机上的独立产品验证。研究方案写好了，也不等于完成统计功效、招募或有效性实验。

## 2. 文档检查

核对所有文件编码、非空、唯一主标题、代码围栏、Markdown 表格、相对链接和每个实际子目录 README；引用键在中央文献表有定义。检查方案中的模型名、研究条件、样本规划、核心 / 可选边界、缓存与长期留存定义一致。

审查公共仓库内容：没有真实参与者数据、凭据、私人通信、健康轨迹或未获许可材料。这个检查不宣称完成安全审计，仅说明本次提交的可观察范围。

提交时基于实际远端 HEAD，保留已有内容，使用非强制更新并核对并发变化。推送后检查远端分支、文件路径及内容哈希；文档发布不触发新产品工作流。

## 3. 产品逐功能验收

沿用 Celestial 的 UI → 正式入口 → 真实能力 → 独立验收思路，参考政策快照见[关联与同步](../08-协作与记录/Celestial关联与同步.md)。每个切片先记录起点、权限、目标、输入、结果、失败和取消。

最少覆盖真实风险：

| 风险 | 有意义的检查 |
|---|---|
| 模型或手表阻塞字幕 | 故意延迟 / 关闭可选后端，核对字幕线程与状态 |
| 旧提示伪装实时 | 重连、补传、晚到模型响应，核对源时间和 TTL |
| 混淆不同来源 | 系统 TTS / 回放 / 外部声音分别标记，检验回灌 |
| 把未知当确定 | 模态缺失、无法归属、未校准概率不生成确定标签 |
| 命令误触 | 候选手势不擅自改变保存 / 上传；关键操作有确认 |
| 清理不完整 | 结束、崩溃、重启和队列 / 日志路径逐项核对 |
| 模型升级改变条件 | 固定版本校验，不匹配时拒绝或创建新实验版本 |
| 只看见按钮成功 | 用实际设备和输出证据区分请求、接受、渲染、物理呈现 |

正式验收记录实际运行的视频、构建 ID、日志和断言；镜片显示无法直接录屏时选择适合的外部观察方法并声明限制。不要以手机镜像证明真实镜片的可读性，也不要伪造纯文档任务的产品录像。

研究材料和失败录像受隐私与同意约束，不能为满足公开证据要求上传参与者画面。公共索引可只保留受控证据 ID、版本、检查方法和结论范围。

## 4. 实验版本冻结

冻结以下内容：研究问题、主 / 次指标、主要对比、样本规划与停止规则、排除 / 缺失处理、材料、标签和歧义规则、分组和随机化、字幕布局、模型与候选池、阈值、TTL、提示槽 / 预算、设备和故障处理。

试点后的修改形成新版本。正式研究开始后的变化记录为偏离或新条件，不能覆盖旧文件制造“原本就这样”的记录。不同硬件或输入路径的结果分层报告。

## 5. 交付清单与独立性

每项交付包含可复现代码 / 配置、使用说明、已知限制、复用与许可清单、数据契约版本、实际运行证据与回退方式。在沿用 Celestial 工程流程的正式产品验收中，按已读政策明确开发、独立验证和修补的主机 / 模型组合；当前文档审读不满足也不冒称满足该运行独立性。

验证范围随风险决定，发现具体缺口再补检查。通过已有门槛后不为追求“更全面”无限新增测试；仍有硬性缺口则保留 BLOCKED 或 NOT_RUN。每种结论绑定当时版本，不将新的 main SHA 写到旧证据上假装已测。
