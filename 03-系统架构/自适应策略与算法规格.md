## 1. 决策问题与不可变边界

在用户已经开启的会话中，对有限候选线索选择 `show`、`defer`、`abstain` 或 `no_op`；目标是在保留稳定字幕与用户控制的前提下，减少无依据、过时或干扰性的补充提示。首年不训练通用情绪识别器，也不以“多显示”作为优化目标。

三个层次不可合并：

1. **观察层**：字幕原文及修订、匿名说话人关联、有效声学特征、设备状态、明确的用户操作。观察也可以错误或缺失，必须携带来源和质量。
2. **候选层**：从冻结词表提出线索，标明观察性描述或有限推断、证据引用、替代解释与失效条件。
3. **呈现层**：确定性控制器核查同意、时效、字幕占位、能力和频率，再决定是否呈现。模型无法绕过该层。

**字幕保护不属于可交换的代价。** `CaptionPipeline` 独占原始转写与修订；DecisionProvider 不得润色、翻译、补全或“纠正”字幕来支持自己的线索。翻译如未来另立功能，也须标成另一数据类型，不能覆盖原文。模型超时不阻塞已有可用字幕；基础输入本身失效时明确显示不可用，不承诺仍有实时字幕。

## 2. 状态模型

会话生命周期与各条数据流的可用性分别建模，避免一个可选传感器断开就使整个会话退出。

| 状态域 | 取值与含义 | 必须执行的转换规则 |
| --- | --- | --- |
| `session_state` | `inactive / preparing / active / stopping` | 只有明确启动且必要权限成立才能进入 active；停止首先更新会话代次，使在途旧请求失效 |
| `caption_state` | `available / degraded / unavailable` | 只描述已验证输入路线；不可用时不延用旧句冒充当前语音 |
| `assist_state` | `enabled / paused / unavailable` | 暂停补充提示可保留用户仍需要的字幕；停止整个会话是另一明确操作 |
| `provider_mode` | `disabled / rules / local-approved / jev-cloud` | 模式与权限由用户设置及控制器决定；模型不能自行切换 |
| `capability_state` | 每项分别记录 supported、permission_granted、verified_on_device、fresh_data_available | 未验证是 unknown；收到手势命令不把 raw_emg 置为可用 |
| `candidate_state` | `new / eligible / deferred / displayed / abstained / rejected / expired / retracted` | 选择性弃权与格式／权限拒绝分别记；延后不延长有效期；源修订可撤回提示 |

`session_epoch` 随停止、重新启动或改变数据使用授权而更新。所有异步结果带回原 epoch；结果到达时重新核查，而非只在发请求时检查。停止后按数据协议处理工作缓存和获准保存的研究记录，不能把“停止”误记为已删除所有第三方或持久化副本。

| 建议动作 | 控制器接受后的语义 | 结束条件 |
| --- | --- | --- |
| show | 请求呈现一个仍有效的候选；只按真实回执更新展示记录 | 原 TTL、源撤回、用户关闭或共用替换规则 |
| defer | 暂不呈现，保留有界候选等待预定重评事件／deadline | 条件改善则重新完整核查；过期则终止，不延长 TTL |
| abstain | 当前候选版本不作推断性呈现，保存最小弃权原因 | 有实质新证据／新版本才可重新产生候选；不因轮询重复试到成功 |
| no_op | 不提出新的呈现或排队动作 | 当前有效内容沿自身 deadline 管理；不能借 no_op 保留已失效内容 |

`displayed` 是带具体回执层级的呈现记录，不代表用户看见或理解；若仅提交请求而没有可验证的渲染回执，不能把状态升级为实际物理呈现。

## 3. 输入特征与时间语义

特征窗口以映射后的源时钟为准；窗口型特征的 `data_age = controller_now - mapped_window_end`。不能用生成、发布或接收时间把旧测量变成新数据。源时间无法映射时记为 unknown；出现无法解释的未来时间或超过冻结的同步误差预算，也不能静默截成零年龄。自动即时线索不以“刚收到”替代数据新鲜度。

| 特征组 | 首版所需字段 | 合法用途 | 不得推导的结论 |
| --- | --- | --- | --- |
| 字幕状态 | utterance_id、revision、stable_text、editable_tail、源窗口、可用性 | 修订传播、与证据对应、占用测量 | 文字一定正确或代表说话人的真实意图 |
| 说话人关联 | 会话内 track_id、unknown/multiple、关联依据与质量 | 合法关联时附着线索；否则保留未知 | 永久身份、仅凭声音确定屏幕位置 |
| 线索证据 | evidence_id、类型、支持窗口、源版本、有效期、替代解释 | 允许词表匹配、失效与去重 | 有一个高分就能跳过证据核查 |
| 显示状态 | 实际布局占用、最近字幕更新次数、已占线索槽、排队量 | 估计当前界面是否拥挤，延后可选信息 | 眼动、注意力或真实认知负荷 |
| 用户与会话 | 开关、静默类别、手动请求、当前模式、授权版本 | 拒绝、偏好与控制优先 | 被动动作等同于明确同意 |
| 平台状态 | 连接、已核实显示能力、输入路线、错误与热量状态（若开放） | 降级、停止或记录设备偏离 | 有硬件传感器就一定有第三方 API |
| 可选本人信号 | 指标、单位、窗口、数据年龄、活动背景、缺失、个人基线版本 | 独立探索中的本人支持候选 | 心率高＝紧张、HRV低＝负面情绪、腕部动作＝心理状态 |

Meta 的运动、输入、语音和部分相机能力在当前 SDK 变更记录中有实验性标记；这些能力不自动提供原始多通道麦克风、眼动或世界锁定锚点。首版只使用实际通过验证的字段，其他保持 unknown。[META-02](https://github.com/facebook/meta-wearables-dat-ios/blob/main/CHANGELOG.md)

### 3.1 显示负担代理量

首版保留三个可解释量：`occupancy`（已用字幕布局面积／可用字幕面积）、`update_rate`（固定窗口内的字幕提交次数）和 `cue_slot_used`。先以布局硬上限处理遮挡，再用冻结的规则判断是否暂缓附加线索；不需要先训练一个“认知负荷模型”。

如离线比较确需单一分数，可试用 `L = w1 × occupancy + w2 × clipped_update_rate + w3 × cue_slot_used`，各输入归一化、权重非负且和为 1。归一化边界与权重由共创和试运行选择、记录并冻结。`L` 只能称为显示负担代理分数；与主观努力量表是否相关是待检验问题，不能靠命名完成效度证明。

## 4. 两层决策：硬门控先于代价排序

### 4.1 所有模式共有的硬门控

以下任一条件成立，禁止自动呈现该候选，记录明确 reason_code；不能用更高模型分数抵消：

- `USER_DISABLED / CONSENT_MISMATCH / SESSION_MISMATCH`：类型关闭、用途不允许、请求来自旧会话。
- `SCHEMA_INVALID / UNKNOWN_LABEL / EVIDENCE_MISSING`：格式错误、标签不在词表、证据不存在或不匹配。
- `SOURCE_REVISED / EXPIRED / TIME_UNKNOWN`：依赖已修订、超期、时间无法满足该即时用途。
- `ASSOCIATION_UNKNOWN`：需要附着人物的线索却无有效关联；可以改为预先设计的无人物未知状态，不能猜一个人。
- `RENDER_UNAVAILABLE / CAPTION_OCCLUSION`：当前实际终端不可用，或会遮挡受保护字幕。
- `FORBIDDEN_ACTION`：要求修改字幕、开启采集、改变授权、外发消息、诊断或执行未许可动作。

用户的暂停、撤回、停止和设备错误可立刻终止当前提示，不受最短展示时间或模型请求完成与否约束。停止入口不能排在普通候选队列后面。

### 4.2 选择性门控与代价

对通过硬门控的候选，首版优先实现可解释的规则顺序：用户手动请求的许可内容 → 证据与有效期 → 不确定性处理 → 显示空间与更新压力 → 去重与稳定性。手动请求不解除权限和证据限制，只改变可选内容的调度优先级。

若有足够、独立的任务标签，可在离线阶段比较下列期望效用形式：

`U_show(c) = p_valid(c) × V(c) - (1 - p_valid(c)) × C_wrong(c) - C_interrupt(c, L) - C_switch(c)`

其中 `p_valid` 是针对明确任务定义、在保留数据上评价的有效性概率估计；`V` 和各代价是研究中可讨论、可冻结的策略权重。它们不是天然存在的客观心理量。先通过硬门控，再与弃权、继续等待的效用比较；不能因为公式给出正值就显示禁止的内容。

最小可实现的比较可把弃权效用定为 0 作为参照，在 `U_show > 0` 且有足够剩余有效期时才进入展示竞争；平局取弃权。defer 只处理可改善的暂时拥挤／槽位冲突，重评时仍用原 TTL。首版不预测未来心理状态或未来收益来证明“值得等”；更复杂等待代价模型须另有数据并在离线比较中说明。

- **未校准时**：不把模型原始 confidence 填进 `p_valid`。允许经批准的、可直接追溯的状态说明；推断性即时线索保持弃权或仅在获批的受控材料研究中测试。
- **有效不等于有用**：线索即使与参考标签一致，也可能多余、分心或不受欢迎； usefulness 与任务正确性分别评估。
- **延后有成本**：仅当仍可能在原有效期内有用时 defer；不通过无限排队掩盖过期。过期归 expired，不记为模型成功。
- **同源分数不独立**：不将 ASR、说话人、线索模型等相关分数直接相乘，声称获得联合正确概率。

## 5. 稳定性、抑制与工程起点

以下仅用于合成回放和早期技术试运行。主研究前必须在版本化参数表冻结；若试运行不支持，应修改或移除，而不是以本文数值为目标硬凑结果。

| 参数 | 初始提议 | 目的与必须保留的例外 |
| --- | --- | --- |
| 同时可选线索槽 | 1 个 | 字幕不计入且优先；零线索是合法输出 |
| 普通事件合并窗口 | 最多 100 ms | 合并同批修订，非固定模型调用频率；停止／撤回不等待合并 |
| 候选初始 TTL | 3 s，仅针对短对话的示例候选 | 必须按类别和源事件定义；不适用于健康样本；实际可缩短 |
| 最短稳定展示 | 1 s | 避免无意义闪烁；证据失效、过期、用户控制立即覆盖，不为凑时长保留错误提示 |
| 重复抑制 | 同源事件、同标签、同说话人 5 s | 不抑制新事件；用户主动再次查看与自动重复分别计数 |
| 候选队列上限 | 8 项 | 优先清除失效项；仍满时按冻结顺序拒收并计数，不偷偷扩容 |
| 模型请求并发 | 每会话最多 1 个 | 候选／证据版本变化才触发；忙时待处理快照有界，不按每帧调用 |
| 模型等待预算 | 不超过 600 ms 且不得超过剩余 TTL | 超时返回规则／弃权；这是起点，不是 Jev 或网络 SLA |
| 显示拥挤恢复 | 高、低门槛分离；低于恢复门槛持续 500 ms 才恢复自动提示 | 门槛数值待布局试运行；从拥挤到正常有滞回，不在边界闪烁 |
| 日常模式自动支持频率 | 默认关闭；开启后起点为每 10 min 最多 1 次、每小时最多 3 次 | 手动请求单独统计；进一步受本人设置与独立协议约束 |

TTL 从源支持窗口或预先定义的事件时间计算，不从“模型终于回复”开始。调度、排队、重试和渲染均消耗剩余 TTL。最短展示时间与切换滞回只抑制非必要切换，不是对错误内容的保护。

有效期必须安排本地 deadline 检查，不能只等下一条输入事件才发现过期；断流后旧提示也应到期撤下。自动请求另受冻结的速率／费用上限约束，不因并发数为 1 就认为请求量已受控。

若两个同等级候选竞争，用冻结的明确顺序处理，例如更早的到期时间、较早的源事件、稳定 candidate_id；不得每次随机抖动。任何效用分数切换余量、类别优先级或规则阈值都写入 policy_revision，不在主研究中随结果调整。

## 6. Jev 与其他后端的受限契约

输入只包含已允许的文本和结构化状态；字段沿用数据契约：`candidates[]`、`evidence[]`、`ttl`、`model_revision`、`calibration_version`，加会话代次、源版本与当前呈现摘要。不能要求 Jev 从原始音频生成字幕；图片能力仍属实验路线，不是首年核心依赖。[JEV-01](https://docs.typesafe.ai/models)；[JEV-03](https://docs.typesafe.ai/images)

| 返回项 | 校验规则 |
| --- | --- |
| action | 只接受 show、defer、abstain、no_op；不是直接设备命令 |
| candidate_id | 只能引用本请求候选，不能新增心理标签或任意文本 |
| evidence_ids | 只能引用本请求且仍有效的证据；不接受凭空补充的“观察” |
| class_probabilities / model_confidence | 可选且分开保存；不得冒充校准后的正确概率 |
| model_revision / calibration_version | 由适配器与实际配置核对；模型回显不能自行证明版本真实性 |
| reason_code | 有限枚举，供审计；不把长篇自由解释当新证据 |

Jev 的 confidence 描述输出概率分布的集中程度；集中不保证事实正确，且并非每个输出类型都带独立 confidence。[JEV-02](https://docs.typesafe.ai/confidence) 应用层只可接受符合 schema 的建议，再执行本地硬门控。语义上错误但格式合法的输出仍可能失败，不能把结构化输出当作模型安全证明。

错误响应、超时、旧版本、陌生 ID、超预算与云授权撤回均触发可预测的降级。云不可用时只承诺已经实现并验证的 rules 或 local-approved 路径，不称为“Jev 离线运行”。不训练客户数据也不等于请求零保留，是否可发送仍由数据协议决定。[JEV-04](https://help.typesafe.ai/articles/5974925716-how-is-submitted-data-used-or-retained)

## 7. 控制器伪代码

下面描述逻辑顺序，具体线程、SDK 和类型尚未实现。字幕更新与普通候选决策隔离；显式控制优先处理。

```text
on_event(event):
    if event is explicit_pause_stop_or_revocation:
        update_user_policy_and_session_state(event)
        advance_control_revision_and_session_epoch_as_required(event)
        reject_new_disallowed_work()
        invalidate_affected_candidates()
        clear_affected_presentation(event)  # 整场停止也清除字幕；仅停提示则保留字幕
        cancel_affected_cancelable_requests()
        stop_affected_sources_if_required_and_apply_retention_policy()
        record_control_receipt_with_actual_ack_level()
        return

    if not valid_current_authorized_source_envelope(event):
        reject_with_reason(event)
        return
    if session_state in [inactive, stopping]:
        reject_late_data(event)
        return
    if event is accepted_caption_update:
        update_caption_pipeline_without_decision_model(event)
        invalidate_candidates_using_older_revision(event)
        render_available_caption_state()

    update_capabilities_clocks_and_freshness(event)
    expire_or_retract_invalid_candidates()
    if session_state != active or assist_state != enabled:
        return

    candidates = bounded_candidates_from_frozen_vocabulary()
    eligible, rejected = apply_common_hard_gates(candidates)
    if research_condition == C0:
        return
    if research_condition == C1:
        decision = common_scheduler(eligible, current_display, user_policy)
        render_with_common_stability_and_actual_receipt(decision)
        return  # 不让 provider 的额外筛选偷偷改变 C1 候选池
    if changed_candidate_snapshot_and_request_budget_available():
        submit_or_coalesce_bounded_request(eligible, current_state, on_recommendation)
    return  # 字幕／显式控制事件不等待 provider

on_local_deadline():
    expire_or_retract_invalid_candidates()
    clear_expired_presentation_and_record_actual_receipt()
    reevaluate_waiting_candidates_with_full_gates_if_session_active()

on_recommendation(request_context, recommendation):
    # 异步返回后重新检查，不能沿用请求时的许可和有效性
    if session_state != active or assist_state != enabled:
        reject_with_reason(recommendation)
        return
    checked = validate_schema_epoch_versions_and_evidence(request_context, recommendation)
    checked = apply_common_hard_gates_again(checked)
    decision = frozen_condition_policy(checked, current_display, user_policy)
    if decision == defer and remaining_ttl <= required_presentation_budget:
        decision = abstain(reason = EXPIRED_OR_TOO_LATE)
    decision = apply_stability_without_overriding_stop_or_expiry(decision)
    render_only_allowed_decision(decision)
    record_minimal_decision_and_receipt(ack_level, evidence_source)
```

主实验重放预先冻结的候选、建议与策略轨迹，不在每次回放重新调用云模型；上述异步部分主要说明开发／实时验证时的隔离规则。C1 直接进入共同调度，不把 C2 provider 已筛剩的列表当作它的输入。

真实实现还须为每个队列设容量、取消和失败路径，并区分“请求提交”“设备接受”“客户端绘制”“独立证实物理呈现”。收到 API 回调不能直接记作用户看见或理解；没有光学证据时物理呈现时间保持 unknown。

| 10:00:00 的事件，TTL 3 s；10:00:04 才收到模型结果 | expired，不显示 | 源时间、接收时间、实际年龄；不能将年龄记为 0 |

| 候选有效但字幕占位已满；等待后源事件过期 | 先 defer，后 expired | 显示负担代理、等待时长、过期，不计为已送达 |

消费 Neural Band 的命令通道与 Aria 研究数据流是不同访问路径；研究流含 EMG 与惯性数据，不证明消费 DAT 自动提供同样能力。[META-03](https://www.meta.com/en-gb/blog/meta-ray-ban-display-ai-glasses-connect-2025/)；[META-04](https://facebookresearch.github.io/projectaria_tools/gen2/ark/client-sdk/changelog)

Apple 的测量、后台 HealthKit 发布与第三方实际收到数据是不同时间；HRV 是间期变异指标，不能从稀疏 BPM 样本伪造。即使数据及时，也不足以证明瞬时心理状态。[APPLE-01](https://support.apple.com/en-us/120277)；[APPLE-02](https://www.apple.com/health/pdf/Heart_Rate_Accuracy_Study_2026.pdf)；[APPLE-04](https://developer.apple.com/documentation/healthkit/hkquantitytypeidentifier/heartratevariabilitysdnn)

## 9. 校准与冻结方法

1. **先定义目标**：每类线索的标签、允许证据、时间容差和歧义处理分别说明。可核对的事件有效性、参与者是否有用和说话人自述是不同变量；不存在通用“情绪真值”。
2. **先划分后选择**：按人、会话／材料分组隔离开发、校准和最终评价；同段对话的相邻窗口不得散到不同集合。跨日可选信号另做日期隔离。
3. **先做可靠基线**：规则、简单分类器和 Jev 使用相同许可输入、词表及候选池。先报告缺失、类别分布与样本量，少量数据不硬拟合复杂校准器。
4. **独立评价**：在未用于调阈值的数据上报告覆盖率—错误率、校准图与分组误差；若输出的是有效概率估计，再报告适合该定义的概率评分。准确率高不自动代表概率校准良好。
5. **选择并冻结**：结合错误代价、可读性、延迟和共创偏好选阈值与去重策略，记录选择依据和失败条件；主研究中不在线更新以追逐效果。
6. **变更即新版本**：模型、词表、提示、ASR、材料、语言或设备变更时评估失配。没有新证据就降级，不能沿用旧校准承诺。

## 10. C0／C1／C2 与验收边界

所有条件共享字幕、源时序、匿名映射、基础硬门控、显示安全上限与队列规则，沿用同一组已选择的初始个人设置。C0 不显示可选线索；C1 为“基础调度辅助”：在共享有效性、容量与基础调度约束下呈现候选，不使用可选的不确定性和显示负担过滤；C2 在同一基础上增加冻结的选择性过滤。

共同调度须明确排队、冲突、替换／覆盖、去重与过期规则，不允许 C1 无限并发、故意恶化其可读性或给 C2 单独放宽 TTL。C1 中遇到共用槽位、TTL 或队列上限也会有未呈现候选，必须记录原因，不能声称所有候选均被实际看到。用户在任一条件关闭或暂停后不自动重开；若切换条件需要恢复初始设置，须按协议提示并取得明确操作，记录偏离与实际暴露。

受控研究的错误探针与日常自动路径分离，按已批准材料和协议呈现，不用关闭共同过期、关闭或权限保护来制造错误。C2 比 C1 提示更少时，只能解释策略整体效果，不能单独归因于校准或负担代理；速率匹配的机制实验另立问题。

| 验收对象 | 需要的证据 | 当前状态 |
| --- | --- | --- |
| 字幕保护 | 模型合法／非法输出均无法改变字幕字节、版本与调度通道的测试 | NOT_RUN |
| 取消与失效 | 撤回、过期、修订、旧 epoch 的夹具与实际入口结果 | NOT_RUN |
| 限流与稳定性 | 极端候选突发、边界负担、重复与恢复的确定性回放 | NOT_RUN |
| 模型契约 | 超时、陌生 ID、非法动作、格式正确但证据错误等测试 | NOT_RUN |
| 研究可复现 | 同一 manifest 下候选、决定、未呈现原因与字幕轨迹一致 | NOT_RUN |
| 实机表现 | 指定版本设备上的可读性、时延、清屏、降级与实际回执证据 | NOT_RUN |

开始实现前仍需冻结：首轮词表和语言、布局占位算法、类别 TTL、所用 ASR、设备路线、选择性门控规则、材料划分与校准目标。它们可在既有授权范围内通过试运行逐项确定，不要求为了文档中的每个参数再设置一轮独立审批。
