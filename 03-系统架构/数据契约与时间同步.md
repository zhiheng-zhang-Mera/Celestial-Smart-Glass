# 数据契约与时间同步

这是后续可执行 schema 的设计说明；当前没有已经实现的 SDK、接口服务或持久化数据库。实现时在 [contracts](../contracts/README.md) 固定 schema 版本，先以合成事件验证，再接真实设备。

## 1. 公共事件封套

| 字段 | 定义 |
|---|---|
| `schema_version / event_type` | 契约版本与明确事件类型 |
| `event_id / session_id / stream_id / sequence` | 去重、会话与流内顺序；重连更换 stream epoch |
| `source_id / source_class / modality` | 来源设备和类别；原始输入、系统输出和回放分开 |
| `observed_at / emitted_at / received_at` | 事件观察、源端发布、协调端收到时间；不可互相替换 |
| `clock_domain / monotonic_time / sync_error_ms` | 时钟域、单调时间、估计映射误差；未知误差保持 null |
| `window_start / window_end / valid_until` | 特征窗口与有效期；没有窗口的单次事件明确表示 |
| `provenance / model_revision / config_revision` | 来源样本、生成模块与固定版本 |
| `consent_scope / purpose / retention_class` | 使用范围、处理目的与保存类别 |
| `quality / missingness / confidence` | 信号质量、缺失原因、模型置信来源及校准状态，三者分开 |
| `payload` | 由 event_type 限定的内容，不允许任意模型字符串变为命令 |

无效与缺失不是数值 0；HR 缺失不表示心率为零，无法归因不表示中性情绪。UTC 便于记录审计，跨设备毫秒级对齐仍需实际时钟映射与误差估计。

## 2. 主要事件

| 类型 | 关键字段 | 约束 |
|---|---|---|
| `Utterance` | utterance_id、revision、language、speaker_track_id、stable_text、editable_tail、source spans | ASR 观察与翻译 / 解释对象分开；修订不得伪装成新发言 |
| `SpeakerTrack` | session_track_id、association_method、location、coordinate_frame、association_quality、last_seen | 匿名且会话内；未知、重叠、失联为合法状态 |
| `CueCandidate` | cue_id、label、observed_or_inferred、evidence_ids、alternatives、valid_until、calibration_version | 窄域标签、证据可追溯；过期后不可补发 |
| `PhysiologyObservation` | metric、value、unit、device / sample_source、window、activity_context、quality、age | HR 与 HRV 指标及窗口写清，不混用 SDNN / RMSSD 等定义 |
| `MotorEvent` | pattern_id、start / end、raw_signal_available、detector_version、quality、activity_context | 动作模式与本人意义分开；研究原始流引用不得公开 |
| `SelfReport` | report_id、prompt_type、noticed、meaning、help_wanted、rating、optional_note | 本人未注意到动作由自述提供，允许未知 / 跳过 |
| `DecisionRecommendation` | candidate_ids、action、evidence_ids、reason_code、model_revision、valid_until | 允许动作仅 show / defer / abstain / no_op；无直接设备执行权限 |
| `PresentationDecision` | recommendation_id、final_action、gate_results、layout、target_device、policy_revision | 由控制器产生，记录最终拒绝原因；模型建议不是最终结果 |
| `UserAction` | action、input_method、explicitness、scope、ack_id | 手动输入与被动 MotorEvent 不混用；保存 / 上传有独立范围 |
| `OutputReceipt` | semantic_unit_id、output_revision、device、started_at、ended_at、status、ack_level、evidence_source | 区分请求发出、设备接受、客户端渲染及已确认物理呈现；不可测时保持 unknown |
| `CapabilitySnapshot` | device / SDK、supported、authorized、verified、current_availability | 不从产品营销描述推断当前 API 访问 |

## 3. 置信度分层

`quality` 表示信号是否可靠；`confidence` 表示某模型在其任务中的输出；`calibration` 表示该输出与已标注任务正确性的关系。三者都不能直接充当“人的真实内心概率”。多个模态可因同一动作共同产生伪影，不按独立证据简单相乘。

没有校准资料时记录 `calibration_status: uncalibrated`。Jev 的置信机制和实际模型版本见[Jev 文档](Jev与可替换模型.md)。对置信阈值的修改形成新 policy revision；主实验配置冻结后不能用测试结果反调阈值。

## 4. 时间对齐

建立每条流的单调时钟到手机协调时钟的映射，记录可测传输往返、偏移及误差。无法获得源单调时间的 HealthKit 样本保留原有时间戳与到达时间，声明其精度边界，不伪造毫秒同步。

肌电、视频或音频需要的对齐精度与生理慢变量不同。嘴部同步或短动作归因在误差高于任务所需时停用；HR / HRV 用较长窗口描述趋势，不把几十秒后送达的数值归因到某个瞬时话语。瞬时样本年龄按源测量时间计算，窗口特征按映射后的源 window_end 计算；不能用特征生成、发布或接收时间代替。映射未知时年龄也未知，数据发布与客户端唤醒延迟单独计量。

流重连后先更新 epoch 和时钟估计，再接收呈现候选。保留来源次序，允许按 event_id 去重；迟到事件可进入经同意的离线分析，但通常不再触发当下提示。

## 6. 状态一致性与修订传播

字幕修订引用前一 revision；由旧文字产生的 CueCandidate 可能失效，应显式撤销或重新生成，不能沿用旧证据。用户关闭推断后控制器立即阻断后续输出，在途响应不能重新开启开关。输出回执只证明其 ack_level 对应的事件：提交、设备接受或客户端渲染不能自动证明实际光学显示 / 声音播放。只有独立证据支持时才记录物理呈现确认；任何级别都不证明用户已阅读、同意或情绪改善。

## 7. 可复现配置

每次正式运行保存不可变 manifest：代码 SHA、构建 ID、设备 / 固件 / SDK、模型与提示模板 revision、schema / policy revision、条件 C0 / C1 / C2、材料哈希、数据切分、随机化种子、时间误差、启用模态和偏离说明。保留的是必要配置与授权日志，敏感正文按研究计划在受控位置保存。
