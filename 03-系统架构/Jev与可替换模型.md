# Jev 与可替换模型

状态：拟议架构与选型依据；未创建模型适配器、未调用生产 API、未完成性能评估。

官方资料核查日：2026-10-22。

## 1. 定位：一个可替换的决策提供方

Jev 的候选角色是根据已提取、可追溯的事件提出有限选项内的判断，例如候选沟通提示是否有足够支持。它不负责音频采集、ASR、心率测量、EMG 解码、时间同步，也不能直接越过用户偏好控制显示。

项目真正要评价的是“在不确定性与有限显示空间下，怎样帮助用户选择、质疑或关闭辅助”，而不是证明某个厂商模型必不可少。模型不能获得独立执行外部动作、改写原始字幕或保存人物长期档案的权限。

## 2. 已核实的产品边界

| 事项 | 2026-10-22 的官方说明 | 项目决策 |
| --- | --- | --- |
| 模型版本 | jev-latest 指向稳定的 jev-1.13.0；jev-preview 指向 jev-1.14.0，后者于 10 月 14 日可用 | 主实验优先验证明确版本 ID；不使用会漂移的别名冻结结果 |

来源：[JEV-01：Models](https://docs.typesafe.ai/models)、[JEV-02：Confidence](https://docs.typesafe.ai/confidence)、[JEV-03：Images](https://docs.typesafe.ai/images)、[JEV-04：数据用途与保留](https://help.typesafe.ai/articles/5974925716-how-is-submitted-data-used-or-retained)。当前公开接入方式见 [Quick start](https://docs.typesafe.ai/introduction/quickstart)；“本次未确认本地部署”是核查状态，不是对厂商所有商业安排的永久否定。

即使返回值符合类型和枚举，也仍可能语义错误、缺乏证据或受 ASR 错误影响。不能沿用“没有自由文本生成，所以不可能误判”的表述。

## 3. 四种运行模式

| 模式 | 行为 | 适用条件 |
| --- | --- | --- |
| disabled | 不运行可选模型决策；控制器不新增该类提示 | 用户关闭、未批准、不可用或基础研究不需要 |
| rules | 根据可审计规则处理有限候选 | 建立可复现基线，验证接口与过期逻辑 |
| local-approved | 使用已获数据与许可批准的本地替代分类器 | 离线需求或云端处理不可接受；需独立评估 |
| jev-cloud | 经批准向版本固定的 Jev 发送最小状态 | 账户可用、条款通过、网络与预算许可 |

这是项目接口约定，不表示这四种后端已实现。local-approved 不是“本地 Jev”；发生超时也不自动把内容转给另一个云厂商。

模式切换须记录原因与版本。主实验中冻结模式及切换规则；不能悄悄更换后端后仍将结果视为同一实验条件。

## 4. 拟议 DecisionProvider 契约

以下名称是本项目拟议的标准化字段，不是声称厂商 SDK 有同名 API。实现前应与系统主协议统一类型、单位、可空值和时钟规则。

### 4.1 请求

| 字段／对象 | 内容与约束 |
| --- | --- |
| request_id、session_id | 不带身份信息的请求／临时会话标识；用于去重与回放 |
| schema_version | 项目协议版本，不与 SDK 版本混淆 |
| candidates[] | 控制器允许评价的有限候选；包含候选标识和已批准类别 |
| evidence[] | 每项证据的来源、事件标识、源时间窗口、质量／缺失状态；推断与观测分开 |
| state_as_of、ttl | 状态对应时刻与允许有效期；明确单位，跨时钟映射可靠后才比较 |
| speaker_attribution | 会话内匿名归属与 unknown 状态；不提供姓名或跨会话身份模板 |
| presentation_state | 字幕占位、已有提示、用户启用类别等必要状态；不伪称认知负荷真值 |
| model_revision | 请求的固定后端版本；实际返回版本还须核对 |
| calibration_version | 适用于该模型、问题与数据域的阈值／校准策略版本 |

默认不把原始音频、视频、EMG、PPG、完整健康历史、联系人或身份信息放入云端 state。自我状态扩展若确有必要，只发送经过批准且足以回答问题的最小派生字段，并保留缺失、过旧和来源不可靠标记。

Jev 官方的基础文本／结构化输入边界见 [JEV-01](https://docs.typesafe.ai/models)。本项目的最小化字段是设计选择，不是厂商自动保证。

### 4.2 返回

| 字段／对象 | 约束 |
| --- | --- |
| action | 仅允许 show、defer、abstain、no_op；只是建议 |
| candidate_id | 必须对应请求内候选，不允许自造新类别 |
| evidence_ids | 只能引用请求中实际存在的证据；缺失时不得补造 |
| selected_class、probabilities | 保留原有任务定义；不同后端没有同等概率语义时不能强行比较 |
| model_confidence | 可空；仅在后端确有该字段或有明确标记的派生统计时提供 |
| model_revision、calibration_version | 保留实际执行版本及所用策略；版本不匹配使该结果失效 |
| status、latency、reason_code | 区分正常回答、超时、限流、拒绝访问、不可用、无效结构和证据不足 |

不强制模型编写解释性长文本。面向用户的原因优先由受控模板和证据类别生成，避免将流畅解释误当作可靠依据。

### 4.3 动作的区别

- **show**：建议呈现；仍须通过控制器的全部检查。
- **defer**：在有效期内等待更充分的证据，不代表无限缓存或继续追踪个人。
- **abstain**：当前判断不可靠、证据不足或不适用；不以猜测补齐。
- **no_op**：没有需要采取的新动作；不等于证明情境不存在任何情绪或沟通问题。

## 5. 不能交给模型的控制职责

最终控制器须独立执行：用户开关与同意范围、来源质量、说话人归属要求、ttl、时钟有效性、去重、占位限制、频率限制、撤回／停止、数据流白名单和异常处理。

数值比较、样本年龄、时间对齐、HR／HRV 指标计算与显示几何约束由可测试的确定性代码完成。Jev 不承担临床判读，不把心率升高或握拳直接映射为焦虑、愤怒或任何“真实情绪”。

如果模型建议 show，但候选已经过期、用户已关闭或说话人仍不明，控制器必须拒绝。模型的高 confidence 不能覆盖这些硬条件。

## 6. 如何理解与验证 confidence

TypeSafe 的 Choice／Score confidence 来自该回答的概率分布，主要表达集中程度；它不是本研究经过验证的“判断正确概率”。Noul 使用一个 yes 概率，没有单独 confidence。多个彼此独立的 Noul 值也不自动构成一个总和为 1 的互斥类别分布。[JEV-02](https://docs.typesafe.ai/confidence)

本项目的拟议验证流程：

1. 先固定问题、类别、标签来源和允许弃答的条件；不把隐藏情绪作为客观真值。
2. 按说话人和会话分割训练／开发／保留测试材料，再设阈值，避免同一人的相似片段跨集合。
3. 在目标语言中单独检查 ASR 错误、重叠、缺失上下文与不同表达方式。
4. 同时报告类别错误、覆盖率、选择性风险、过期率、错误归属与实际延迟；不是只报平均 accuracy。
5. 有可靠参考标签时，评价类别概率的校准；不能直接把 confidence 当概率画出“正确率校准”并宣布可信。
6. 模型、提示、类别、阈值或输入分布变化后重新验证。高集中度但错误的样本保留为失败案例。

官方模型文档提示语言表现并不一致，英语以外内容需在实际数据上测试；中文／本地语言能力不能从英文示例推断。[JEV-01](https://docs.typesafe.ai/models)

## 7. 保留、离线与异常处理

TypeSafe 的“不训练客户请求／响应”不等于零保留。其说明还涉及服务提供、计费、防滥用和遥测；实际保留／删除取决于适用协议、数据类型、法律要求与所约定的 ZDR。企业 ZDR 是需另行确认的安排，不是默认账户属性。[JEV-04](https://help.typesafe.ai/articles/5974925716-how-is-submitted-data-used-or-retained)；[JEV-04B：Legal](https://docs.typesafe.ai/legal)

在机构批准前，云端测试仅使用合成或明确允许的材料。批准至少涵盖目的、字段、处理方、地区／跨境条件、保留、删除、遥测、退出方式和账户责任人。没有确认的期限应写成“尚待协议确认”，不能自行填写零天或固定天数。

运行异常遵循以下拟议规则：

- 给请求设置不长于其有效期的 deadline；重试不延长 ttl。
- 429、网络失败和权限失败各自记录；不通过无限重试掩盖不可用。
- 不缓存未获批准的原始对话；缓存键也不得泄漏身份信息。
- 超时后禁用相应可选提示；字幕能否继续取决于独立音频／ASR 路线，不能一概保证。
- 只在已批准和预先定义的条件下转入 rules 或 local-approved；否则保持 disabled。
- 日志记录版本、动作、原因码与延迟，不记录 token、完整云请求或敏感原文作为默认调试输出。

## 8. 选用 Jev 的决策门槛

在相同冻结事件与候选池上，与 rules 和一个许可合适的紧凑替代方案比较。只有在任务效果、延迟、可解释失效、隐私和成本之间有可证实的收益，才保留 Jev 为主后端。厂商吞吐或低延迟宣传不能替代本项目的端到端测量。

上线到参与者会话前必须具备：固定 model_revision、问题／schema 版本、calibration_version、允许动作集、缺失和过期测试、日志审查、账户预算限制、数据流批准和不依赖该服务的停止控制。当前这些条件都没有被标记为已完成。
