# 平台验证记录模板

状态：`PLANNED`。本文件提供后续执行的 spike（短时能力验证）步骤和证据表；以下所有本项目设备、SDK、模型与健康数据检查均为 `NOT_RUN`，不是已经通过的测试报告。

基准日：2026-10-22。适用范围：现有、借用或另行获准取得的商业／研究设备；不要求自制 PCB、光学组件或传感器电路。使用前先读[平台能力与证据](平台能力与证据.md)及[实机验证与替代路径](实机验证与替代路径.md)。

## 1. 使用规则与记录层级

每次执行复制一份记录到机构批准的项目记录位置，填真实时间和实际版本。公开仓库只放无敏感信息的摘要、合成夹具与结论；不放健康样本、原始音视频、设备序列号、账户、令牌或第三方未公开访问材料。

状态只用 `PASS / FAIL / NOT_RUN / NOT_APPLICABLE`；被权限阻挡且未测试时写 NOT_RUN，并将对应工作项标 BLOCKED。NOT_APPLICABLE 必须说明研究设计为何不需要，不得用来掩盖没有权限。

| 证据层级 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 文档 DOC | 官方描述支持该能力或限制 | 本项目账号、设备已经可用 |
| 接口 API | 选定程序发出请求并收到真实响应 | 眼镜实际显示或用户看见 |
| 客户端 CLIENT | 客户端／模拟器完成绘制或处理 | 目标光学显示完成、真实设备性能 |
| 实机 DEVICE | 指定设备可观察到输出／采集事件 | 物理呈现的精确时刻，除非有独立时间证据 |
| 独立时间证据 TIMED | 经过时钟映射的外部记录支持某时刻或区间 | 用户阅读、理解、同意或获益 |
| 用户研究 USER | 获批协议下的理解、偏好、舒适度等记录 | 接口全面正确、长期效果或普遍有效 |

`OutputReceipt` 保留 `ack_level` 与 `evidence_source`。只有提交回调就写提交；只有模拟画面就写模拟；无法测量眼镜物理呈现时间则保留 unknown。商用相机／手机的获准观察记录可以提供有限时间证据，但须说明帧率、观察方法和误差，不把摄像时间当作精确设备时钟。

## 3. 推荐执行顺序

先完成 PV-01、PV-02 和 PV-05，确保合法访问与停止路径；再按所选核心输入路线完成 PV-03、PV-04、PV-06 和 PV-09。PV-07／PV-08 是单独选择的可选分支；没有 HR 或 raw EMG 不阻塞核心回放研究。PV-10 在前述检查足够后做整合验证。

发现权限拒绝、发布资格不符或未批准数据用途时停止相应分支，记录已完成的只读证据。不得通过更换账号、提取应用内部凭证或绕过保护来继续。

### PV-01：能力与访问清单

1. 记录设备实际型号；先区分 Meta Ray-Ban Display、无显示 Ray-Ban Meta 和 Aria 研究设备，不用品牌相近替代具体型号。
2. 在当次官方说明与 SDK 变更记录中核对显示、输入、语音、相机／音频、运动能力及实验性标记；保存 URL、访问日期和对应版本。
3. 用获准账号和正式测试入口完成注册／配对，逐项请求最小权限；记录批准、拒绝、unknown，不批量假定全部允许。
4. 导出最小 CapabilitySnapshot；对眼动、原始阵列麦克风、世界锁定锚点、连续 raw EMG 等无已核实入口项保留 unknown／不可用。
5. 核对实验所用分发路线是否允许该功能；“可编译”不等于“可发布”。

**通过依据**：目标最小路线的实际权限、版本、可测试方式可追溯；未知能力被隔离。实验性 API 可测试但发布受限，是当前 SDK 明确约束，不能以买到设备替代访问资格。[META-01](https://developers.meta.com/wearables/device-access-toolkit/)；[META-02](https://github.com/facebook/meta-wearables-dat-ios/blob/main/CHANGELOG.md)

**当前结果**：NOT_RUN。若无法合法运行目标显示路线，继续模拟与材料研究，并缩小对目标眼镜的结论。

### PV-02：显示、可读性与物理回执

1. 用同一固定脚本准备 20 条合成文字：短句、两行长句、数字／标点、目标语言字符、未知说话人标签、修订尾段、错误状态和清屏。
2. 先在模拟界面检查换行和溢出，再在实际目标设备重复；两种结果分别保存，不相互替代。
3. 运行 3 次各约 20 分钟的技术会话，记录实际长度；至少覆盖连续更新、静止文本、补充线索加入／撤回，以及一次按官方操作断开与恢复；自然发生的断连另行记录。
4. 对每次输出记录提交时间、实际返回的回执类型；可获准独立观察时记录光学可见性与时间误差。无法拍清时只给观察结论，不编造光学延迟。
5. 在长句、快速更新和只有一条附加线索时操作“只看字幕”、暂停提示和停止会话，检查字幕是否被覆盖、旧提示是否残留。

**通过依据**：所用字符、布局、清屏和停止均有实机证据；未通过的显示状态不会继续作为有效输出。可读性由先导参与者再验证，技术人员看得清不等于所有目标用户可读。20 条与 3 次会话仅是初始取样，不构成稳定性保证。

**当前结果**：NOT_RUN。物理显示未证实则最多标记客户端通过。

### PV-03：输入、字幕、修订与声道

1. 选定一种实际可用路线：官方语音转写、获准音频输入后自选 ASR，或授权回放。明确当前是在验证实时能力还是回放能力。
2. 使用 5 段约 30–60 秒的获准／合成材料，覆盖单人、两人轮流、重叠、静音／输入中断、背景噪声；三人情况按核心材料需要补测。
3. 如收到音频帧，记录实际采样率、声道数、格式、时间戳和丢帧；如只收到转写，明确没有验证原始音频。单路音频不能被写成已获得独立麦克风阵列。
4. 对每段记录首个部分字幕、稳定提交、后续修订及匿名说话人状态。源时间可靠时分别计算相应延迟；否则记录时间边界未知。
5. 断开输入并恢复，验证“输入不可用”、未知说话人和旧修订失效；未验证方向定位时不显示实际方位。

**通过依据**：每条字幕可追到源材料／窗口和版本；输入错误可见且不伪造新鲜内容。目标语言准确率、重叠性能与可读性阈值由后续材料评估确定，不以一次演示替代。

**当前结果**：NOT_RUN。实时输入不达标时核心可改用固定字幕回放，但不得声称实时 ASR 已通过。

### PV-04：显式控制与误触恢复

1. 在手机保留可直接使用的停止入口；手势控制是补充，不是唯一退出方式。
2. 对实际开放的确认、暂停、略过各做 10 次有意触发，记录输入来源、收到事件、控制决定与用户可观察回执。
3. 再做至少 10 个普通活动片段作为早期误触排查，例如自然摆手、调整姿势；不把这点样本当完整误触率评价。
4. 重复输入、断连和在途模型返回时操作关闭，确认旧结果不能重新开启提示。
5. 保存／上传等改变数据使用范围的操作仍须明确确认；被动 MotorEvent 不得进入同意通道。

**通过依据**：命令语义、误触与恢复可追溯；手机停止独立可用。消费 Neural Band 的处理后控制事件不是连续肌电样本；收到点击不证明用户意识或心理状态。[META-03](https://www.meta.com/en-gb/blog/meta-ray-ban-display-ai-glasses-connect-2025/)

**当前结果**：NOT_RUN。手势不可用不阻塞手机控制基线。

### PV-05：时钟、乱序、过期与停止

1. 在合成回放中注入已知延迟、乱序、重复和源时钟未知事件；每个夹具先写预期结果，再执行。
2. 分别用即时样本和窗口型特征验证 age：后者从映射后的 `window_end` 计算，不从收到请求开始计时。
3. 发出一个延迟返回的模型请求，在其返回前修订源字幕、关闭提示或结束会话；预期旧版本／旧 epoch 被拒绝。
4. 检查过期候选是否从队列和显示中撤下；另测完全没有后续输入时是否仍由本地 deadline 触发撤下。最短展示时间不能压过过期和停止。
5. 对实际设备断连重连重复一次，分别记录控制器拒收新工作、数据流停下、客户端清屏、物理清屏的证据层级与时间。

**通过依据**：每个夹具的预期与实际一致；不能校准的源时间不冒充即时。停止后的新工作拒收可在控制器日志验证，但在途采集／第三方副本是否停止或删除须另外证实。

**当前结果**：NOT_RUN。停止、授权隔离或过期保护失败时暂停整条受影响的自动提示路线。

### PV-06：模型适配与失效隔离

1. 先用 rules 和合成响应测试适配器；只有明确允许云处理时才用实际 Jev 测试账号与无敏感输入。
2. 为合法返回及至少下列异常建立夹具：非法 action、未知 candidate_id、缺失 evidence、旧版本、过期回复、格式错误、超时、超额、撤回后的回复、格式合法但证据矛盾。
3. 逐项确认不会改写字幕、开启权限或直接向设备下达任意命令；核对模型仅返回有限动作建议。
4. 分别记录 provider 延迟、控制器延迟、候选年龄、超时与降级；不同阶段不能只合成一个“模型快”的指标。
5. 确认 confidence 原值与任何校准结果分开，保存实际模型版本而非仅用可变别名；固定材料回放不重复随机调用云模型。

**通过依据**：合同错误被拒绝且可用字幕不被模型阻塞；校准未完成不承诺预测准确性。Jev 的 confidence 是分布集中量，图片接口实验性，文本／结构化接口不是原始音视频 ASR。[JEV-01](https://docs.typesafe.ai/models)；[JEV-02](https://docs.typesafe.ai/confidence)；[JEV-03](https://docs.typesafe.ai/images)

**当前结果**：NOT_RUN。云数据处理条款未落实时只测合成适配与获准本地路线，不开通或发送真实参与者信息。

### PV-07：可选 Apple Watch 时效与授权

1. 仅在该分支获准后，使用自愿者与获准应用取得本人对应数据类型的授权，记录 Watch／iPhone 型号、OS、设置及可用指标。
2. 分别在应用前台、后台和手机锁屏状态安排约 20 分钟的低风险观察；记录实际场景和缺失，不伪装 workout 会话来获得高频后台权限。
3. 对每个样本保留源窗口／采样时间、可观察的发布信息、接收时间和可见时间。某层不可观察就标 unknown，不补造发布时刻。
4. 测试撤回授权、关闭有关测量设置、暂时断连和重新连接；晚到数据不能触发关于“此刻心理状态”的断言。
5. HRV 仅使用实际可读的指标及其定义；未返回 HRV 是可接受的缺失结果，不由 BPM 间隔拼出 HRV，也不假定 raw PPG 可读。

**通过依据**：获得的是经授权、含可解释来源与年龄的样本；将实测年龄分布与预先定义用途比较，决定是否只适合会后概览。Apple 的 5 秒级测量描述、后台 HealthKit 30 秒发布描述和自有应用实际投递不是同一个保证；设备更换不自动解决传输时效。[APPLE-01](https://support.apple.com/en-us/120277)；[APPLE-02](https://www.apple.com/health/pdf/Heart_Rate_Accuracy_Study_2026.pdf)；[APPLE-03B](https://developer.apple.com/documentation/WatchConnectivity)

**当前结果**：NOT_RUN。HRV 缺失或年龄不适合即时用途时关闭相应自动功能，不影响核心字幕研究。

### PV-08：可选研究级 raw EMG 路线

1. 先确认书面研究访问、可用采集硬件与兼容软件组合；单独记录消费 Display／Neural Band 控制路径与研究采集路径，不能互相替代权限。
2. 在获准 Aria Gen 2 ClientSDK 路线核对实际版本、回调与校准字段；2.5.0 引入 Neural Band 的 EMG、加速度和陀螺仪 batch，当前文档另有 2.5.1，须锁定实际测试版本。[META-04](https://facebookresearch.github.io/projectaria_tools/gen2/ark/client-sdk/changelog)
3. 将 Aria 到主机的控制连接与数据连接分开记录：该 ClientSDK 的 BLE 用于配对、状态和控制，记录／传流走 USB 或 Wi-Fi；这不说明腕带到 Aria 的内部链路是什么。[META-04](https://facebookresearch.github.io/projectaria_tools/gen2/ark/client-sdk/changelog)
4. 先做短时、本人同意的静息、指定手部动作、普通活动与重复佩戴片段；记录通道、单位、实际采样、校准、丢包和时钟，而不是先输出情绪标签。
5. 若另行研究个人习惯，先由本人定义可观察动作，独立划分天数与活动负例；技术 spike 只确认可采集和可对齐，不证明自发、无意识动作可被可靠分类。
6. 停止与撤回后检查研究数据流及本地缓冲；研究采集设备不是 Display 的显示替代品，其重量、连接和现场负担另记。

**通过依据**：实际拿到的确为已授权 raw 数据与有效校准，而不是仅有 gesture 类别；能够解释时间和缺失。没有访问时该分支 BLOCKED，不能仅因官方文档存在就标通过。[META-05](https://ai.meta.com/aria-application/)

**当前结果**：NOT_RUN。连续 EMG 无法落实时保留手动标记或已开放命令，不采购更多消费腕带来猜权限。

### PV-09：数据退出、保留与成本

1. 用合成事件核对采集开关、云开关、研究保存开关分别生效，未选择的路径无新事件。
2. 枚举工作内存、排队请求、重试、缓存、日志、获准研究存储和外部服务各自责任；停止与删除是不同操作。
3. 对已授权删除范围执行删除测试并记录实际回执；失败时保留错误与待处理范围，不写“所有副本已删除”。
4. 模拟模型请求／费用上限、网络失败与重试，确认有界且不会自动购买额度；本地停止不依赖云调用。
5. 对云服务核对实际合同与保留设置；“不用于训练”不作为“零保留”的证据。[JEV-04](https://help.typesafe.ai/articles/5974925716-how-is-submitted-data-used-or-retained)；[JEV-04B](https://docs.typesafe.ai/legal)

**通过依据**：每项数据和支出路径有已核实范围、退出动作、责任人与失败处理；不能检查第三方内部副本时写合同边界，而非技术删除保证。

**当前结果**：NOT_RUN。

### PV-10：整合会话与降级

1. 用同一合成／获准输入完整运行一次约 30 分钟会话；该时长仅为早期起点，后续应覆盖拟研究场长。
2. 在预定事件点依次触发模型超时、输入中断、显示断连、数据过期和用户关闭，记录顺序与实际恢复。
3. 比较 C0／C1／C2 的字幕文本、时间、修订与未知状态、初始个人设置是否一致；共同检查容量、排队、冲突、替换／覆盖和过期。对 C2 选择性过滤与共同调度限制分别计数；C1 不应被设计为无限并发或更差的基础调度，用户关闭后不得自动重开。
4. 按设备分别记录电量变化、可观察温度／热状态、异常退出与可读性问题；不因计算卸载到手机就声称整套系统节能。
5. 将基础链路成功、可选链路失败和实际显示终端的偏离分别报告，给出继续、缩减或停止建议。

**通过依据**：正常入口可完成最小任务，故障可解释、可停止、可降级；未达到全时长稳定性不得外推全天使用。

**当前结果**：NOT_RUN。

| PV-xx-a | 未记录 | 执行前填写 | 未测试 | 未记录 | 未记录 | NOT_RUN | 未记录 |

证据位置指向机构批准位置的最小定位信息；公开摘要不直接暴露个人原始数据路径。关键失败应附“复现前提 → 操作 → 实际现象 → 对比预期 → 已排除因素 → 下一步”，不得只写“偶尔不稳定”。

## 5. 汇总与 gate 决定

| gate | 对应主要检查 | 当前结果 | 未满足时的可行路线 |
