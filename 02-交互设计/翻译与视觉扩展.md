# 翻译与视觉扩展

这些内容保留 Idea Book 的完整产品方向，属于首年核心之后的开发范围。每个扩展应作为独立切片验证，不将多语言、双向播音、OCR 和世界锚点同时作为首篇研究的前提。

## 1. 一个解释核心，多种输出

同一语义单元只维护一个带版本的翻译状态：`semantic_unit_id → translation_id / revision`。眼镜文字、耳机译音和对外扬声器订阅该状态，不各自重新翻译。原始识别、译文、摘要和社交解释是不同对象，任何后级不能覆盖上游原文。

共享短期上下文保留当前语言、近期话轮、会话内发言人、临时实体 / 术语、可修订内容和已输出版本。菜单中识别的词可以成为后续 ASR / 翻译的候选，但必须保留“视觉来源建议”，不能硬改用户实际说出的话。

## 2. 双向口译与输出提交

对方讲话可经 ASR 与翻译送到佩戴者耳机 / 字幕；本人讲话可译成指定语言送到对外扬声器。两条路径有独立的输出授权，避免将私密提示公开播出。

文字可以修订，已经播放的声音不能收回。TTS 维持尚可替换的 speculative 队列；确定提交后生成 playback receipt。否定、转折、条件、语序变化和人物 / 数字等内容需等待足够语义证据。Fast / Balanced / Stable 是待评估偏好，不代表保证低延迟。

用户耳返若设备支持，走本地低延迟音频路径，不绕行 ASR、翻译或 Jev。没有可核实的耳返接口时不模拟为已支持。

## 3. 防反馈与声音优先级

来源类别至少区分 `human_self`、`human_external`、`environment_text`、`system_tts`、`system_sidetone`、`system_ar_overlay`。播放器保留时间区间和已知输出，结合可用回声消除及时间相关性识别回灌。标签本身不能让混合麦克风信号自动分离，必须实测串音、漏音和延迟漂移。

由用户选择字幕优先、耳译优先或有限混合，避免三路持续争夺注意。对外 TTS 需要明确开始 / 停止和错误后的更正策略；长延迟时宁可停下，不在话题已转换后继续旧译音。

## 4. 视觉文字旁注

用户通过已核实眼动、视野中心停留或手动选择锁定现实文字。头部朝向不能冒充眼睛看向哪里。最小版本采用手动 / 视野中心选择，建立短命 `TextAnchor`，保留原文，译文放在可读的旁注位置。

`TextAnchor` 包含来源帧 / ROI、观察文字、推断补全、译文、坐标系、置信来源、最近观察时间与 TTL。没有空间追踪时仅使用图像或屏幕坐标，不宣称锚点留在真实世界。追踪丢失则淡出或回到固定卡片。

计算按缓存 / 跟踪 → 快速 OCR → 多帧增强 → 较强视觉识别逐级升级；云端升级需要单独授权。艺术字体和残缺文字的猜测必须与实际观察区分。停留 200–400 ms 等原始设想只作为试点候选，不是已证明的理想阈值。

## 5. 场景切片

| 切片 | 首个可验证版本 | 后续能力 | 关键指标 |
|---|---|---|---|
| 菜单 / 标签 | 手动选区、OCR、原文旁注、单语对 | 临时术语共享和多帧增强 | 识别与翻译错误、操作次数、遮挡 |
| 书籍阅读 | 当前段落选择、段落缓存 | 邻段消歧、页内锚点、轻量预读 | 重复识别、阅读连续性、漏行 |
| 双向对话 | 手机麦克风 + 一条翻译 + 一个输出 | 眼镜 / 耳机输出路由 | 端到端延迟、意义错误、反馈回路 |
| 复杂字体 | 可追溯观察与候选补全 | 强模型按需介入 | 错误补全、增量收益、成本与隐私 |

## 6. 扩展通过门槛

需要证明单一语义状态在多端一致、系统输出不重复进入理解链、原始观察与推断分开、用户可停止公开播音、会话清理覆盖所有输出队列。新增功能分别记录语言、设备、网络和数据条件；原型成功不自动证明全天候可靠或专业口译质量。
